- (constraint) [INHERITED] Stack tecnológica: Frontend em React, Backend em Java Spring Boot, Banco de Dados PostgreSQL.
- (decision) Paradigma de API: Comunicação Frontend-Backend via REST API clássica (JSON).
- (decision) Paradigma de Backend: Monolito Modular. Divisão estrita em pacotes por domínio (ex: Finanças, Usuários, Infra/Configuração). Isso evita acoplamento excessivo mas mantém o deploy simples.
- (decision) Gerenciamento de Estado (Frontend): Zustand. Escolhido por ser leve e moderno, sem overengineering, perfeito para gerenciar estados globais vitais (como o 'Mês Selecionado').
- (decision) Isolamento de Dados (Multi-tenancy): Isolamento Lógico na coluna 'usuario_id'. Todas as entidades core terão essa coluna e todas as queries serão filtradas pelo ID do token autenticado.
- (decision) Consumo de API e Cache: React Query (TanStack Query). Escolhido por abstrair o controle de loading, cache e repetições automáticas em caso de erro de rede.
- (decision) Segurança de Autenticação: Token JWT armazenado em HttpOnly Cookie. Evita vulnerabilidades de XSS comuns no armazenamento via LocalStorage.
- (constraint) [INHERITED] Versionamento de Banco: Flyway. O esquema do banco será versionado via scripts SQL e não por geração automática do Hibernate.
- (decision) Estilização Frontend: Vanilla CSS / CSS Modules. Máxima flexibilidade e controle sem dependência de frameworks utilitários pesados.
- (event) spine finalized
- (decision) UPDATE - Estilização Frontend: Migrado de Vanilla CSS para Tailwind CSS v4. Escolhido por acelerar o desenvolvimento, garantindo consistência com variáveis CSS nativas e perfeita aderência ao ecossistema React.
- (decision) Fluxo de Autenticação Duplo: Suporte nativo ao Google One Tap (validação via google-api-client no endpoint POST dedicado) mantendo o fallback para OAuth 2.0 padrão (via Spring Security oauth2Login). Binds: A arquitetura de validação de login. Prevents: Substituição irresponsável de fluxo seguro ou validação manual/vulnerável de JWT. Rule: Frontend implementa o prompt One Tap e despacha a credential via POST. Backend valida o token via GoogleIdTokenVerifier. O fallback OAuth continua acessível.
