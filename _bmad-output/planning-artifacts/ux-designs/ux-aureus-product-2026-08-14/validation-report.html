Validation Report — Aureus UX

DESIGN.md: DESIGN.md
EXPERIENCE.md: EXPERIENCE.md

Veredito Geral

Os contratos de UX estabelecem uma fundação limpa, robusta e muito bem alinhada com os requisitos da V1. Os revisores notaram excelente disciplina em cortar itens fora do escopo (ex: Dark Mode, i18n). No entanto, há lacunas críticas em Acessibilidade (navegação por teclado/leitor de tela) e na Documentação de Componentes visuais (Modais, Estados de Carregamento e Fluxo de Login) que precisam ser cobertas antes do hand-off final para desenvolvimento.

Findings (Achados)

Crítico (4)

  • Rubric Referências Visuais Faltantes: Os documentos DESIGN.md e EXPERIENCE.md não possuem links para os arquivos `.html` de wireframe que geramos.
    Correção: Adicionar links para os HTMLs nas seções pertinentes.
  • Rubric Componentes sem especificações visuais: Modal/Bottom Sheet, Empty State e Filter Toggle foram citados no comportamento, mas faltam no DESIGN.md.
    Correção: Adicionar os specs na tabela de componentes.

Alto (2)

  • Acessibilidade Navegação por Teclado: Falta especificar o "focus trap" (travar o foco) dentro dos Modais/Bottom Sheets.
    Correção: Adicionar regra em EXPERIENCE.md > Accessibility Floor.
  • Acessibilidade Leitores de Tela (Grid): A tabela de consolidação de 24 meses é super complexa. Falta orientação técnica de ARIA para leitura semântica.
    Correção: Adicionar diretriz de ARIA Labels.

Médio (6)

  • Estrutura Fluxo de Login (FR-34, FR-35): O PRD exige Autenticação via Google e Local, mas não há menção a isso nos fluxos.
    Correção: Adicionar "Flow: Login" no EXPERIENCE.md.
  • Estrutura Nomes dos Blocos de Consolidação: O DESIGN.md resume a "Receitas, Despesas, etc", mas o PRD exige nomes exatos: "Receitas por Conta", "Despesas por Conta", "Categorias (R$)" e "Categorias (%)".
    Correção: Refinar a redação no DESIGN.md.
  • Rubric Loading States: Não definimos como a tela fica enquanto os dados carregam.
    Correção: Definir o Cold-Load State (spinners vs skeletons).
  • Rubric Grid Empty State: Como a tela de Consolidação fica no dia 1, sem nenhuma conta cadastrada?
    Correção: Descrever o empty state para a aba Consolidação.
  • Rubric Failure Paths Faltantes: Faltam caminhos de falha nos fluxos 1 e 3.
    Correção: Adicionar caminhos de falha (ex: timeout de rede).

Baixo (4)

  • Estrutura Seletor Rápido de Mês Inicial (FR-25): Além do swipe/setas, falta dizer se há como "pular" direto para 12 meses atrás sem apertar a seta 12 vezes.
    Correção: Especificar se a Label do mês é clicável para abrir um modal de seleção.
  • Estrutura Bloqueio Rígido (FR-31): Impedir cadastro sem dependências deve ser listado explicitamente nas regras de erro.
    Correção: Citar em Error States.
  • Rubric Protagonistas Genéricos: Os Key Flows usam "User" em vez de personas específicas.
    Correção: Ajustar a semântica.
